# Plan 3 execution debt — api-and-jobs

Recorded 2026-08-27 at the end of subagent-driven execution of
docs/superpowers/plans/2026-08-27-api-and-jobs.md. The SDD workspace that
held the full ledger is deleted; git history plus this file are the record.

## Spec divergences shipped knowingly

1. **Spec step 5.3 is not implemented.** The advisory lock is taken after
   `provider.resolve()`, so it serialises the write but prevents no
   duplicate provider calls. Fixing it properly means holding a DB
   transaction across an ~8s HTTP call; the alternatives are a
   session-level lock, a short 'resolving' claim marker, or accepting the
   duplicates. Now honestly described in the code rather than misdescribed.
2. **Batch misses are not enqueued.** Spec's Batch form says "misses are
   enqueued"; the implementation resolves every item inline and reports a
   hardcoded per-item status of 200. So the durability guarantee does not
   hold for anything submitted via `items` — which is the endpoint the
   spec's /corpus runner is meant to use. A pending item should be 202.
3. **`parsed` differs between POST and GET.** It is null on a cache hit but
   populated by the poll endpoint, though the spec says GET returns "the
   same envelope". `readLookup` already LEFT JOINs `parses`; adding
   `p.tokens` to that select closes it.

## Operational debt

4. **Cron invocation duration vs DEFAULT_LIMIT.** 25 jobs x 8s is up to
   200s of sequential work and no route exports `maxDuration`. The lease
   reaper makes a mid-sweep timeout recoverable, so this degrades
   throughput rather than destroying work — but a repeatedly-interrupted
   job can reach `abandoned` carrying a stale `last_error`. Fix by setting
   `maxDuration` or lowering DEFAULT_LIMIT so the worst case fits.
5. **`enqueue` does not reset `attempts` when reviving an `abandoned` job.**
   After the 12h window a repeat request revives it, the next sweep spends
   one attempt, and the max-attempts guard abandons it again. The safety
   net is permanently dead for that lookup while the request path keeps
   retrying. One line in the ON CONFLICT clause.

## Deferred minors

6. `envNumber` duplicated across four modules. **The copies are not
   identical** — two use parseInt, two use parseFloat, and each is right
   for its variable. Any unification must use parseFloat: a naive
   parseInt version would floor CONFIDENCE_FLOOR=0.75 to 0 and mark
   everything resolved.
7. Per-job TMDB client rebuilds the token bucket inside the sweep loop, so
   the bucket bounds nothing there. Adequate only while the loop stays
   sequential; revisit before parallelising it.
8. The cron-route test monkeypatches `globalThis.fetch` because the route's
   `sweep()` call has no `fetchImpl` seam. Order-fragile. A ten-line
   `handleSweep(deps)` extraction mirroring lookupHandler would close it.
9. `job.category as Category` in sweep.ts. Safe (the column is a PG enum);
   type-clean version is typing `ClaimedJob.category` and casting once in
   the row mapper.
