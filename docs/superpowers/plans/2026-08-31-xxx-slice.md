# The xxx Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parse xxx scene filenames, validate the grammar against 12,815 real names, and resolve them against theporndb.net into `media`, `scene_details`, and `people`.

**Architecture:** A new `lib/parse/scene.ts` that `parseVideo` dispatches to on `category === 'xxx'`, anchored on the `site . YY.MM.DD` prefix that 77% of real names carry. A new `lib/providers/tpdb/` mirroring the existing TMDB provider exactly. `PipelineDeps.provider` becomes `providers: readonly Provider[]` so a mixed-category batch picks the right one per item.

**Tech Stack:** TypeScript, Next 16, zod 4, drizzle-orm, node:test. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-31-xxx-slice-design.md` — read it first; every number in this plan comes from measurements recorded there.

## Global Constraints

- **Never use the `any` TypeScript type.** The codebase has two sanctioned exceptions, both documented at their use site: the immediate argument of a zod parse, and a value serialised wholesale and never read field by field. Both use `unknown`, not `any`.
- **Prefer async APIs over sync twins.** `fs.promises` over `fs.*Sync`. `*Sync` is allowed only in scripts that do one thing and exit, and must say why.
- **The parser is pure and deterministic.** No clock, no network, no randomness. `normalized_key` derives from the parse; a parser whose output depends on when it ran produces two cache keys for one name.
- **Never let a credential reach a command line or the logs.** `TPDB_API_KEY` is read from `process.env` only. Never interpolate it into a shell command — a failing command echoes its whole argument list. `provider_calls` records the path, never the URL with its query.
- **Every test must be able to fail.** Before trusting a passing test, change the implementation and watch it fail. A loop whose body never runs, an assertion against a literal the test built itself, and `every()` on an empty array are the three shapes this codebase has caught repeatedly.
- **Confidence floor is `0.75`** (`CONFIDENCE_FLOOR`), a fraction not a percentage.
- **`duration` from TPDB is seconds.** Verified over a 25-scene sample: min 1920, median 2340, max 3060.
- **Run tests with** `node --env-file-if-exists=.env.local --import tsx --test <file>`. `npm run test -- <file>` does NOT filter — the script ends in a glob.
- **Node 24.** Use `export PATH="$HOME/.nvm/versions/node/v24.20.0/bin:$PATH"` if the default node is newer.
- **Commit after each task.** Do not push.

- [ ] **Step 3: Implement the date rule**

```ts
const DATE = /^(\d{4}|\d{2})[.\-_](\d{2})[.\-_](\d{2})(?![\d])[.\-_ ]?/;

/**
 * The leading date of a scene name, or null.
 *
 * Pure by contract: `YY` always becomes `20YY` and no value is checked
 * against today. Sanity-checking a year against the current date would make
 * the parse non-deterministic, and `normalized_key` is derived from it.
 */
export function parseSceneDate(text: string): { readonly iso: string; readonly rest: string } | null {
  const m = DATE.exec(text);
  if (m === null) return null;
  const [, rawYear = '', rawMonth = '', rawDay = ''] = m;
  const month = Number(rawMonth);
  const day = Number(rawDay);
  // 1.6% of date-shaped triples in the corpus are not dates.
  if (month < 1 || month > 12 || day < 1 || day > 31) return null;
  const year = rawYear.length === 4 ? Number(rawYear) : 2000 + Number(rawYear);
  const iso = `${String(year).padStart(4, '0')}-${rawMonth}-${rawDay}`;
  return { iso, rest: text.slice(m[0].length) };
}
```

- [ ] **Step 4: Implement `parseScene`**

The shape, with the reasoning that must survive in comments:

```ts
/** Scene-local junk. NOT shared: `xXx` (2002) is a real movie title. */
const SCENE_JUNK: ReadonlySet<string> = new Set(['xxx', 'pmv']);
```

Algorithm:
1. `stem` from the split. Strip a trailing group with the existing `splitGroupSuffix`.
2. Try `parseSceneDate` against the stem. If it matches at position 0 the stem has no site, which does not occur in practice but must not crash — treat `site` as null. Otherwise find the first date-shaped run and treat everything before it as the site, everything after as the title run. Use `parseSceneDate` on the remainder after each candidate boundary so the month/day guard applies.
3. With a date: the title run is *already known to be title-only*, so use `findTitleRegion`. Its docstring forbids `findBoundary` here.
4. Without a date: the stem is a whole release name, so use `findBoundary` — the same call the movies path makes.
5. Drop `SCENE_JUNK` tokens from the title in both branches.
6. `site`: the head before the date; else `split.ancestors[0] ?? null`.
7. `hints.fromDirectories`: every ancestor, always.
8. `categoryDisagreement`: true when a season/episode marker is present.

- [ ] **Step 3: Implement the strategy**

Ordered, first hit wins, each step one call, a step with absent inputs is skipped not failed:

| Step | Query | Confidence |
|---|---|---|
| 1 | `site_id` + `date` | 0.98 |
| 2 | `site_id` + `date - 1 day` | 0.90 |
| 3 | `site_id` + `date + 1 day` | 0.90 |
| 4 | `q` = `<site> <title>` | 0.85 if the returned `site.short_name` equals the parsed site; else 0.70 single result, 0.60 best-of-many |

Date arithmetic must not go through the local timezone. Use a UTC-safe shift:

```ts
function shiftDay(iso: string, days: number): string {
  const at = new Date(`${iso}T00:00:00Z`);
  at.setUTCDate(at.getUTCDate() + days);
  return at.toISOString().slice(0, 10);
}
```

This is not a clock read — it is arithmetic on a value from the filename — so it does not violate parser purity, and it lives in the provider rather than the parser regardless.
